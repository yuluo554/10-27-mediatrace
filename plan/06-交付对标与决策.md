## 六、装订期与 M1 实测缺陷（2026-10-27，踩到并已修）

> 这一节是"门自己也会坏、也会漏"的证据留档（**B1–B8**）。每条都写了**症状 → 根因 → 修法 → 复验**。
> B1–B7 = 阶段 0 装订期；**B8 = M1 收尾期**（脚本靶子写死 M1，一翻 ✅ 即自崩）。

### B1 · 状态判据误把"提交材料表"当成里程碑表

- **症状**：布局门报 `M1..M4 在副本间不一致（done vs pending）` + `HANDOFFS 缺 4 份` + `LEDGER` 8 行误报；三项连环红。
- **根因**：`STATUS_LINE` 是"行首是 M 号就算状态行"。`plan/00 §四` 的提交材料实物表首格是
  **模块名**（`| M1 结构规则 | … |`），被读成"M1 已完成"，而 `plan/05` 里 M1 是 ⬜ → 判"跨副本不一致"。
- **修法**：改为**按表头定位**（同一行含「状态」且含「阶段/里程碑」），表格结束即停。
- **复验**：`M4.STATUS` 变异（只改 README 的 M2）仍变红 → 判据没被改死。

### B2 · 变异脚本污染仓库（不回滚 + 定位错行）

- **症状**：跑完 `node tools/verify-layout-gate.mjs` 后三个文档被改坏（`M1 状态`被写成 ✅、
  提交材料表的"核验命令"列被换成 `✅ 已完成`、台账多出一行靶子），随后门变红 3 项，
  **看起来像门坏了，实际是变异没还原**。
- **根因**（两条，都是真缺陷）：
  1. `setStatus` 用"行首 M 号"定位 → 改的是 `plan/00 §四` 的**核验命令列**，状态格根本没动；
     于是"变异无效果"，而 `mutate()` 的替身检查只在**内容没变**时抛错，改错地方同样"有变化"→ 不抛。
  2. `compose(...)` 收的是**已应用的 restore 函数**：第 2 个工厂抛错时，第 1 个已落盘的改动**永不还原**。
- **修法**：`setStatus` 改为与门同一口径的"按表头定位"；`compose` 改为收**工厂**并在应用阶段
  出错时**回滚已成功的那些**。
- **复验**：修后连跑两遍变异，四个文档 `diff` 与备份逐字节相同（4× `UNCHANGED`），门仍全绿 19 项。

### B3 · 文档化的参数形态被 parser 拒绝

- **症状**：`mediatrace audit <file> --json`（README 与 `plan/01 §七` 都这么写）直接 exit 3
  （`exactly one file path is required`）。
- **根因**：Go `flag` 包遇到第一个位置参数即停止解析，`--json` 变成第二个位置参数。
- **修法**：`parseInterspersed` 逐段解析，允许旗标与位置参数任意交织。
- **复验**：`TestParseInterspersed`（7 组形态）+ `TestNaiveParseWouldFailTheRegression`
  （**阳性对照**：证明朴素 `fs.Parse` 确实会把 `--json` 留在位置参数里，否则那条回归测试是空的）。

### B4 · 本机无 `make` / Windows 可执行后缀

- **症状**：`make x` 全部 command not found；`spawnSync bin/mediatrace` 即使文件存在也 ENOENT。
- **根因**：本机未安装 make；Windows `CreateProcess` 要求 `.exe`。
- **修法**：新增 `tools/tasks.mjs` 作为**唯一可执行的跨平台入口**，`Makefile` 退为薄委托；
  文档里所有命令改为 `node tools/tasks.mjs <target>`（保留 3 处"本机无 make"的说明性文字）。
- **复验**：`node tools/tasks.mjs all` 全绿；`grep "make <target>"` 只剩说明性条目。

### B5 · 变异脚本改错**列**（B2 同类缺陷的第二次形态）

- **症状**：`M5.HANDOFFS` 变异跑完报"红了但不是 `LAYOUT.HANDOFFS`；实际红: `LAYOUT.STATUS`"——
  看起来像门张冠李戴。
- **根因**：`setStatus` 改的是**最后一个单元格**。`plan/05` 的状态表是
  「阶段 | 名称 | 状态 | 出口门」，末列是**出口门** → 状态格没动，行内仍含 ⬜，
  于是跨副本不一致被 `LAYOUT.STATUS` 抓到（M1 在 plan/05 仍 pending、另两处 done）。
  与 B2 同源：**按位置定位而非按语义定位**。
- **修法**：改成"按表头找『状态』列 + 按表头限定表域找行"，行、列都按语义定位。
- **复验**：`M4.STATUS`（改 README 一处）→ 红于 `LAYOUT.STATUS`；
  `M5.HANDOFFS`（三处翻 ✅ + 藏交接单）→ 红于 `LAYOUT.HANDOFFS`。两组各自命中预期判据。

### B6 · `.gitignore` 的 `out/` 把真值台账一起忽略了

- **症状**：`git check-ignore -v fixtures/out/manifest.json` 命中 `.gitignore:150:out/` ——
  本该入库的 manifest 被静默排除，`check-fixtures` 在干净 clone 里必然失败（缺件）。
- **根因**：`out/` 是"任意层级名为 out 的目录"，而 `fixtures/out/manifest.json` 恰在其下；
  后面虽然有 `!fixtures/out/manifest.json`，但**目录先被排除后，文件级 `!` 无法复活**
  （git 语义：父目录被忽略则其内文件不参与匹配）。
- **修法**：把 `out/` 改成 **`/out/`（仅顶层）**；`fixtures/out/*` + `!fixtures/out/manifest.json`
  继续按"样本不入库、台账入库"工作。
- **复验**：`git check-ignore -v` 三态——manifest 只命中 `!` 例外（= 不忽略）、`*.mp4` 命中、
  `bin/` 命中；并做成常驻断言 `check-ignore-rules`（含阳性对照实测：改回 `out/` 必红）。

### B7 · 当前棒缺入口交接单，两道门全绿（**由用户发现**）

- **症状**：阶段 0 骨架收尾后，`plan/HANDOFF-M1.md` **不存在**；
  `node tools/tasks.mjs gates` 与 `verify-gates` **全部全绿**，没有任何东西变红。
- **根因**：`checkHandoffs` 只对**已 ✅ 的里程碑**要求交接单 —— 而"阶段 0 完成、M1 未开工"
  这个状态下**没有任何判据要求 `HANDOFF-M1.md` 存在**；可恰恰在这个状态下它最必需
  （跨对话上下文不可恢复，`plan/00 §六` 明写"续接第一件事是读 HANDOFF"）。
  **这是"判据覆盖不到当前状态"的典型：门全绿不等于该做的事都做了。**
- **修法**：
  1. 补写 `plan/HANDOFF-M1.md`（七节齐：进度+证据 / **当前事实·状态不变量** F1–F10 / 待办 /
     K 口径清单 K1–K10 / 环境坑 E1–E6 / DoD checklist / 命令速查）；
  2. 新增判据 `LAYOUT.HANDOFF_ENTRY` = **当前棒必须有七节入口交接单**（只断言"有文件"不够，
     必须断言七节齐 —— 否则空文件也能过）。全完成态下退化报"不适用"。
- **复验**：新增两组变异 —— `M5b`（藏掉当前棒的入口交接单）与 `M5c`（把它的第二节改名），
  **两组都必须红于 `LAYOUT.HANDOFF_ENTRY`**；跑后仓库 `diff` 与备份一致（未被污染）。

### B8 · 变异靶子依赖"进度状态"，M1 一翻 ✅ 就自崩（**M1 收尾时踩到并修**）

- **症状**：M1 真收尾、三处副本把 M1 翻成 ✅ 之后，`node tools/verify-layout-gate.mjs` 立刻
  报 5 项疑似假门：`M5.HANDOFFS`/`M5b`/`M5c` 均"变异过程异常"，连 `FINAL.layout` 也红。
- **根因**：靶子被**写死成 M1**。M1 一旦是 ✅，`setStatus(..., "M1", "✅ 已完成")` 就抛
  "变异无意义"（门认为该格已是对拍值），`hide("plan/HANDOFF-M1.md")` 也从"当前棒的入口交接单"
  变成"某历史交接单"——红错判据。这**违反了本脚本文件头自己写的纪律**：
  "变异靶子不得依赖某个特定进度状态……一律用'直接改/删某文件'的形态"（B2/B5 同源：骨架期
  图方便写死了 M1，收尾即暴露——假门族 ⑭ 的实例）。
- **修法**：全部靶子改为**从仓库状态现算**：
  - 新增 `statusRows()` / `milestones()`（**与布局门同一定位口径**：表头含"状态"且含
    "阶段/里程碑"），得出 `FIRST` / `CURRENT` / `LAST_DONE`；
  - `M4.STATUS` 只改一处副本的**当前棒**；`M5.HANDOFFS` 翻目标棒 ✅ 再藏其交接单；
    `M5b`/`M5c` 用 `makeCurrentLeg()`（有待办就用它；全 ✅ 则先把首个里程碑三处一致翻回 ⬜
    造出当前棒，否则 `HANDOFF_ENTRY` 退化"不适用"→无红可验）；
  - `M6.GAPS`/`M8.DOC_TOOLS` 用 `appendToFirstGapCell()`（按"缺口"表头 + 首个数据行**结构定位**，
    不再 grep 写死的缺口句子）；`M7.LEDGER` 用 `insertLedgerRow()`（按"承诺+状态"表头插入）；
  - `M10.RELEASE` 按发布里程碑当前是否 ✅ 二选一（未 ✅ 翻它；已 ✅ 藏留档）。
- **复验**：M1 三处副本已 ✅ 的当下，`node tools/verify-layout-gate.mjs` → **21/21 全绿**；
  跑前跑后 `git status` 一致（无残留）。此后每棒收尾翻 ✅ 都不需要再改变异脚本。

> **纪律固化**：新增/修改任何判据时，变异靶子必须能从**当前仓库状态**现算出来，
> 不得指向某个"此刻恰好待办"的里程碑——否则下一棒一翻状态脚本就崩。
