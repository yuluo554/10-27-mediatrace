## 一、介绍：打印不等于判定

一个 MP4 文件里的时间轴，至少有六种"说法"：

1. `stts` 累加出来的**样本时长总和**；
2. `mvhd.duration` / `tkhd.duration` 声明的**轨道时长**；
3. `elst` 各段 `segment_duration` 之和（**放映时长**）；
4. `elst[i].media_time` 指定的**媒体内起点**（`-1` 为空 edit 的标记，见 M2 规则要点 3）；
5. `ctts` 推导出的 **PTS** 与 `stts` 推导出的 **DTS**；
6. `tfdt` 给分片轨道的**解码基准时间**。

规范允许这些值在编辑、裁剪、分片、转码之后各自漂移。**工具们把每一条都打印出来，但不告诉你它们互相矛盾**：你把 `ffprobe` 的输出喂给 MediaInfo，两者报的时长不一样，你得自己判断谁错、错在哪一字节。

本项目的判定对象只有一句话：

> **同一个文件内部，多条时间轴口径是否互相自洽；不自洽时，差在哪个盒子、哪一字节、差多少。**

不是"这个文件符不符合规范"（MediaConch 已停更且偏格式合规），不是"两个文件哪个好"（Bento4 `Mp4Diff` 是原子比对），不是"这个文件在 mpv/Chrome/QuickTime 里表现是否一致"（见 §十 非目标）。

### 2.2 三条结构性空档

1. **打印与判定之间的空档**：`-diso` / `Mp4Dump` / `-infox` / MediaInfo 文本 / `console.warn` 都把事实摆出来，但**没有一条规则把它们互相比较并给出裁决**。
2. **同一文件内的口径冲突未见有人处理**：跨工具比对是另一件事（且不可复现，见 §十），而**文件自身内部**的 `stts`/`elst`/`mvhd`/`tfdt` 互斥是可以纯字节判定的——检索窗口内**未见有人做**（⬜ 软论据，不作"无人做"的绝对断言）。
3. **"判不准"没有出口**：现有工具要么断言（可能错），要么静默（`console.warn`）。本项目要求一切不可判必须落 `gray` 并可导出，**不伪造 fail，也不假装 pass**。

### 2.3 红海警告（必须随题记录）

- 播放器侧（mpv/VLC/iina）与解析库侧（go-mp4/mp4-rust/MP4Parse/mediabunny）**极度过剩**，任何"再写一个 MP4 解析器"的形态都没有位置。
- dump 类工具（MP4Box `-diso`、Bento4 `Mp4Dump`、MediaInfo）已成事实标准，功能不缺。
- 唯一"判定"形态的 MediaConch **已停更五年**（最后 push 2021-09-29），说明**判定类工具的商业/维护动机薄弱**——这是本题的定位理由，也是**风险**（本项目同样面对维护成本，故首期范围必须窄，见 §十）。
- 低星同题仓库已出现（`peaBerberian/AISOBMFFWVDFBUTFAII` 15★ 只做盒子检查），必须靠**规则化判定 + 证据结构 + gray 出口**拉开差异，不得靠"功能更多"。

## 五、任务要求（首期 M1–M5）

统一约束（对五个模块都成立）：

- **只读**：输入文件以只读方式打开；**不解码**任何样本数据（不读 `mdat` 载荷语义，只按 `stsz`/`stco`/`stsc` 校验区间）。
- **确定性**：同一输入两次运行输出逐字节一致；规则是纯函数（文件字节 + 已解析结构 → 判定），不读时钟、不读随机、不访问网络。
- **证据结构**：每条 `fail` 必须携带 `byte_offset` + `field_path`（统一用斜杠盒路径，如 `moov/trak[0]/edts/elst[1].media_time`；索引从 0 起，按文件内顺序）+ `values`（各口径原值）+ `delta`。四元组口径见 `data/README.md` §5.7。
- **三态输出**：`pass` / `fail` / `gray`。`gray` 表示"证据不足以判定"，**永不折算成 pass，也不升级成 fail**。
- **模块化**：任一模块可单独运行（`--modules M2`），互不依赖对方的内部结构。
- **编号说明**：本文的 `M1`–`M5` 一律指**模块**；`plan/00` 里的 `M1`–`M6` 指**里程碑**（阶段）。`--modules` 只接受**模块号**；里程碑与模块的权威映射见 `plan/00` §五 的"对应模块"列。

### 模块 M1 · 结构自洽

- **输入**：MP4/MOV（ISO BMFF 盒子树）。**首期不做 MKV**（非目标，见 §十）。
- **输出**：`StructureFinding[]`（`too_small_size` / `child_overruns_parent` / `duplicate_moov` / `stco_out_of_mdat` / `ftyp_brand_mismatch` / `truncated_mdat`）。
- **规则要点**：
  1. 每个盒头的 `size` 与实际边界一致（`size==1` 的 64 位 largesize、`size==0` 的"到文件尾"两种合法形态都要正确展开）；
  2. 子盒区间 ⊆ 父盒区间（父盒内含 `meta` 这类 FullBox 的 4 字节 version/flags 偏移要算对）；
  3. `moov` 唯一、`mdat` 唯一；**双 `moov` = fail**（不取"第一个"或"最后一个"了事）；
  4. `stco`/`co64` 的每个偏移 + 对应 `stsz` 条目长度 ⊆ 某个 `mdat` 的载荷区间；
  5. `ftyp` 的 major/compatible brands 与 `moov` 内实际编码（`stsd` 样本条目类型）不自相矛盾。
- **验收**：对合成"**双 moov / stco 越界 / 截断 mdat**"三例，命中率 **3/3**，误报 **0**。
- **确定性纪律**：盒子遍历必须**迭代而非递归**（深盒子树不爆栈），并记录遍历深度；对 `size` 异常只报一次、不连环报（同一根因合并为一条 finding）。

### 模块 M2 · edit list vs 真实时长

- **输入**：`moov/mvhd`、每轨 `tkhd`、`stbl.stts`、`edts/elst`、`mdhd.timescale`。
- **输出**：`DurationFinding[]`，每条至少给出三口径原值与差值：`sum(stts[i].count × stts[i].duration) / timescale`、`mvhd.duration`/`tkhd.duration`（按各自 timescale 换算）、`Σ elst.segment_duration`。
- **规则要点**：
  1. 三口径互比，容差与对齐口径见 `data/README.md` §5.1；
  2. `elst[i].media_time` 与首帧 PTS 的关系（首帧 PTS 应落在该段 media 区间内）；
  3. 空 edit（`media_time == -1`）的语义：**只贡献放映延迟，不引用媒体数据**——报出其贡献的 `segment_duration` 与由此产生的起始偏移；
  4. `media_rate != 1` 必须**显式报出条目号**，并且**不得**把该段的 `segment_duration` 简单当作等速推进（本项目不判"变速是否正确"，只判"声明与结构能否对上"）。
- **验收**：
  - 用 GPAC `-edits` 造 3 段 `elst`（含 `media_rate≠1`），**每条能定位到具体 `elst` 条目号**；
  - 能复现 S1（SO Q56468034）类"copy 前后时长差"：构造"输入 3 条 `elst` + 输出失配"的合成对，报告须指出差异出在 `elst` 而非 `stts`。
- **确定性纪律**：`elst` 多段时按**文件内顺序**编号（`elst[0]` 起），**不排序**——排序会掩盖"段次序错了"这类真实缺陷；`mvhd.duration==0`（分片文件的常见合法形态）时以 `mehd`/末段 `tfdt`+`trun` 推出预期值，推不出则 `gray`。

### 模块 M3 · 时间戳单调性与 timescale 精度

- **输入**：`stts`（DTS）、`ctts`（PTS 偏移）、`mdhd.timescale`、`trex`/`tfhd`/`tfdt`/`trun`（分片）。
- **输出**：`TimestampFinding[]`（`dts_regression` / `dts_overflow_risk` / `timescale_suspect` / `vfr_detected`）。
- **规则要点**：
  1. 由 `stts` 推 DTS：**单调不减**；`dts_n + count × duration` 不得越过该轨道时间字段的位宽（`stts` 用 32 位、`tfdt` 有 version 0/1 之别 → 分别按实际 width 判，不假设 64 位）。容差与"回退"的定义见 `data/README.md` §5.4（**0 容差**）；
  2. `timescale` 是否为常见值或**极小值**（溢出前兆）——白名单与阈值见 `data/README §5`（工程口径，非规范条款）；
  3. `stts` 条目数 > 1 → 标 **VFR（gray）**：VFR 本身不是缺陷，只是"后续基于恒帧率的推断不可用"；
  4. B 帧导致的 PTS/DTS 交错**不是**回归：只在 DTS 上判单调，并在 `ctts` 缺省时明确写"PTS 与 DTS 同序"。
- **验收**：
  - 对"**回退 DTS**"合成文件报出**字节偏移 + 回退发生的样本序号**；
  - **对含 B 帧的正常文件不误伤**：回归集 **≥20 个正常 H.264/H.265 文件，误报 0**。
- **确定性纪律**：样本级遍历只保留**最近一个 DTS 与首个回归点**（不落全量样本表，避免大文件内存爆炸）；回归一经发现即定位到 `stts` 条目号，不再继续扫全轨（首个违规即结论，其余计数只用 `--all` 显式开启）。

### 模块 M4 · 起始偏移与 priming / encoder delay

- **输入**：`elst` 首段（`media_time > 0` = 起始裁剪）、音频轨 `sgpd`/`sbgp`（roll 距离）、`edts` 存在性、首帧 PTS/DTS。
- **输出**：`OffsetFinding[]`（`start_trim` / `priming_undeclared` / `priming_mismatch` / `no_edts_but_nonzero_start`）。
- **规则要点**：
  1. `elst[0].media_time > 0` ⇒ 起始裁剪量 = `media_time / timescale` 秒，必须报出秒值与样本数；
  2. 音频空 edit（`media_time == -1`）+ `sgpd`/`sbgp` 的 roll 距离 vs **期望 priming**：AAC 常见 **1024**（亦见 **2112**），Opus **312** —— 这些是**常见观测值，不是规范强制**，因此只能判"与声明是否一致"，不能判"必须等于 1024"；
  3. `edts` 缺失但 `stts` 首帧非 0 起（或多轨起点互不相同）⇒ `gray`；
  4. 期望值不可判（容器未给 roll 距离、编码未知、`media_rate≠1` 导致采样数不可线性换算）⇒ **输出 `gray` 而非 `fail`**。
- **验收**：
  - 对"**1024 samples 晚**"合成文件报出 **1024**；
  - 对**已正确用 `elst` 裁剪**的文件**不报**：正反例各 **5 个**；
  - 期望值不可判的样本必须落 `gray` 且可导出。
- **确定性纪律**：`gray` 必须带 `reason` 枚举（`no_roll_distance` / `unknown_codec_priming` / `media_rate_not_one` / `no_edts`），**禁止**用 `gray` 兜住解析错误（解析失败是 `error`，不是 `gray`）。

### 模块 M5 · 旋转 / SAR / HDR / 色彩标记矛盾

- **输入**：`tkhd` 的 3×3 matrix（16.16 定点，ISO 14496-12 §6.2.2）、`tkhd.width/height`、`pasp`、`colr`、`mdcv`、`clli`、`stsd` 内编码参数。
- **输出**：`DisplayFinding[]`（`matrix_not_orthogonal` / `rotation_dimension_conflict` / `sar_dar_conflict` / `hdr_metadata_missing` / `hdr_range_suspect`）。
- **规则要点**：
  1. matrix 正交性（旋转/翻转变换的行列式与正交性检查），并识别 ±90° 旋转；
  2. 旋转 ±90° 时 `tkhd.width/height` 的**呈现宽高**应与存储宽高互换——`width < height` 且无 `pasp` 说明时标 `rotation_dimension_conflict`；
  3. `pasp.num/den` 与 DAR 一致性（`DAR = (stsd 宽 × pasp.num) / (stsd 高 × pasp.den)`）；
  4. `colr == bt2020` 类广色域但无 `mdcv`/`clli` ⇒ **`gray`**（元数据缺失不等于缺陷，播放器可能按默认处理）；
  5. `mdcv`/`clli` 的亮度量程自检（`max > min`、`clli` 与 `mdcv` 的 `max` 不矛盾）——**只做量程与互斥检查，不判"绝对亮度是否正确"**。
- **验收**：
  - 对"**matrix=±90 但 width<height 且无 pasp**"合成例命中；
  - 对**正常竖屏手机视频**（matrix=90 + 合理 `pasp`）**不报**。
- **确定性纪律**：matrix 解析按 16.16 定点**整数运算**（不做浮点近似后比较），正交性容差以 1/65536 为单位定义在 `data/README §5`；`colr` 多实例时按文件内顺序全部列出，**不取第一个**。

### 扩展项（二期，首期不做）

- MKV 侧的时间轴语义（`TimestampScale` / `Cluster`/`BlockGroup` / `DefaultDuration` 交叉校验）——首期不做，列为非目标（EBML 结构层同样不做，见 §十）；
- 分片 MP4 的完整 `sidx` ↔ `moof` 索引自洽；
- 逐样本 PTS/DTS 全量导出（首期只给首个违规点）。

## 十、边界与非目标

**不做（首期红线）**：

1. **不做跨工具一致性预言** —— 即"同一文件在 mpv / Chrome / QuickTime 里表现是否一致"。理由三条：违反"只读字节、不解码"前提；需拉多平台播放器，**跨平台不可复现**；结论是**非确定性**的（版本、GPU、系统解码器都会影响），无法做 precision/recall 门禁。
   **但**把"**同一文件内两条时长口径不一致**"（S7 的 2× 时长、S1 的 copy 前后差）**吸收进 M2** —— 那件事是纯字节可判定的。
2. **不做媒体标签/元数据审计** —— AtomicParsley 771★ 只读写 iTunes 标签、mutagen 1981★ 已覆盖；本题不碰 `©nam`/`©too` 这类字段。
3. **不做损坏文件修复** —— `untrunc` 1954★ 是写操作且需参考文件；本题只判定、绝不写回输入文件。
4. **不做纯 MKV 校验器** —— `mkvalidator` 已存在（`foundation-source` 67★，**本次未亲自运行**），单格式太窄；**MKV 首期完全不做**（含 EBML 结构对应项），列二期。
5. **不做 A/V 同步测量** —— `av-drift-detector`（0★）方向已占，且**必须解码**才能测漂移；本题只在**元数据层**判"声明之间是否自洽"。
6. **不做"绝对亮度/绝对色彩是否正确"** —— 只读元数据无法确证像素实际色彩；M5 只做量程与互斥检查。
7. **不做跨平台差异归因** —— S9 那类"Linux 没事、Windows/OSX 有事"只作动机，不进判定路径。
8. **不做自动修复、不做重写容器、不写回源文件**。
9. **不做"哪个工具对"的裁决** —— 不点名 ffprobe/MediaInfo 谁错，只报"本文件内这 N 条口径互斥，差值 X"。

**隐私红线**：纯本地、**零网络**（无遥测、无版本检查、无在线样本拉取）。真实样本只读、不入库；报告默认不写绝对路径。

**品牌隔离**：本仓库文档不提及本系列任何其它项目；涉及相邻方向时一律用方向级描述，不落具体项目名。

**首期范围限定**：容器 = **MP4/MOV**（ISO BMFF，含分片），**不含 MKV**（非目标，列二期）；模块 = M1–M5；不解码、不联网、不修复。非 ISO BMFF 输入（纯文本 / MKV / 随机字节）一律 **exit 3**（无法解析，不进判定通道，见 `data/README §5.6`）。
