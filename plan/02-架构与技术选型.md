## 一、分层

```
┌──────────────────────────────────────────────────────────────┐
│ cmd/mediatrace            CLI：参数解析 / 退出码 / 首屏        │
├──────────────────────────────────────────────────────────────┤
│ internal/report           三态模型 + 证据四元组校验 + 双轨渲染 │
├──────────────────────────────────────────────────────────────┤
│ internal/rules/{module}   M1..M5 纯函数规则（file bytes+IR → findings）│
├──────────────────────────────────────────────────────────────┤
│ internal/isobmff          迭代式盒子遍历 → IR（只读字节，不解码）│
├──────────────────────────────────────────────────────────────┤
│ internal/policy           数值口径常量（唯一实现处）            │
├──────────────────────────────────────────────────────────────┤
│ internal/mkv              EBML 结构对应项（仅 M1 使用）         │
└──────────────────────────────────────────────────────────────┘
tools/fixture-gen           程序化构造 C1–C7 → fixtures（不参与交付二进制）
```

**依赖方向是单向的**：`cmd → report → rules → isobmff/mkv → policy`。
`policy` 不 import 任何内部包；`isobmff` 不 import `rules`；规则之间互不 import。

### 1.1 为什么规则与渲染分家

`plan/01 §七` 要求 JSON 与 Markdown **同源**：先算一次，再渲染两份。
故规则层只产出 `[]report.Finding`（纯数据，不含格式），渲染层只消费同一份 `Report`。
**判定与呈现分家**的另一收益：`--json` 与默认 Markdown 的 finding 集合可按 fingerprint 对拍。

### 1.2 为什么遍历必须迭代

盒子树可以很深（`moov/trak/stbl` 已 4 层，恶意/畸形文件可造上千层）。
递归遍历在畸形输入上爆栈 → 违反"只读审计器不因输入崩溃"。故 `internal/isobmff` 的
walker 用显式栈 + 显式深度上限（超限产生 `max_depth_exceeded` 结构 finding，不 panic）。

### 1.3 只读与确定性

- 输入以 `os.Open` + 只读读取；**不写回、不 rename、不建临时文件在输入目录**。
- 不读时钟、不读环境变量参与判定、不访问网络（`net` 包在 `internal/` 内**零引用**，由 AST 守门）。
- 输出确定性：finding 排序键 = `(module, byte_offset, field_path, rule_id)`，
  JSON 用 `encoding/json` 固定结构体字段顺序（避免 map 迭代顺序）。

### 1.4 解析的 IR 形态

```go
type Box struct {
    Type       string   // 4cc
    Offset     uint64   // 盒头起始绝对偏移
    HeaderSize uint64   // 8 / 16 / 到文件尾形态
    Size       uint64   // 含头的总长（size==0 → 到文件尾）
    Payload    []byte   // 仅当需要子盒解析时切片；大 mdat 不读入
    Children   []*Box
    Depth      int
}
```

`stsz`/`stco` 这类计数表按需解析成结构体（`SampleTable`），**不保留全量逐样本表**
（M3 纪律：只留最近 DTS 与首个回归点）。

## 二、构建

### 2.1 工具链与环境事实（本机实测）

| 项 | 事实 | 影响 |
|---|---|---|
| Go | **不在 `PATH`**；实际位于 `C:\Users\<user>\go-sdk\go\bin\go.exe`（`go1.24.5 windows/amd64`） | `tools/tasks.mjs` 自动探测；可 `GO=... node tools/tasks.mjs test` |
| **make** | **本机不存在**（实测） | `Makefile` 只是薄委托；可执行入口是 `node tools/tasks.mjs <target>` |
| **Windows 可执行后缀** | `bin/mediatrace` 直接 spawn = ENOENT；必须 `.exe`（实测） | `tasks.mjs` 按平台拼名；CI 产物名不带后缀 |
| Node | `v24.15.0`（在 `PATH`） | 两个门 + 任务运行器用 `.mjs`，零依赖 |
| Python | `3.8.8`（在 `PATH`；3.12 在 `AppData\Local\Programs\Python\Python312`） | **项目不使用 Python**：生成器也用 Go，避免版本下限面 |
| ffmpeg | 8.1.1 可用 | **仅生成期/CI 造真实样本真值**，绝不进交付二进制路径 |
| MP4Box / GPAC | 本机未安装 | M2 复现 S1 类需在 CI 安装 GPAC；本机缺失项按 ⬜ 登记（`plan/05 §已知未验证项`） |

### 2.2 单二进制度量

- `go build -trimpath -ldflags "-s -w -X main.version=..." -o bin/mediatrace ./cmd/mediatrace`
- 零第三方依赖：`go.mod` 的 `require` 块必须为空；`go.sum` 不存在（**由门断言**）。
- 可证伪：`ldd bin/mediatrace`（Linux）/`otool -L`（macOS）无 `libav*`；
  把 `ffmpeg` 从 `PATH` 移除后 `mediatrace audit` 行为不变（CI 有一条 `env -u` 步骤）。

### 2.3 任务入口（骨架期已落地，**本机实测**）

> ⚠️ 本机**没有 `make`**（实测 2026-10-27），Windows 上 `bin/mediatrace` 也不能直接执行
> （需 `.exe`）。因此**可执行的唯一入口是 `node tools/tasks.mjs <target>`**；
> `Makefile` 只是薄委托。文档里写 `make x` 时，等价命令是 `node tools/tasks.mjs x`。

| 目标 | 作用 | 出口 |
|---|---|---|
| `bin` | 构建 `bin/mediatrace`（Win: `.exe`） | 产物在 `bin/`（不入库） |
| `test` | `go vet ./...` + `go test ./...` | 全绿 |
| `gates` | 布局门 + 脱敏门 | 全绿，且两门都打印扫描计数 |
| `verify-gates` | 两门的变异验证（21 组） | 全绿 = 每条判据都被证伪过一次 |
| `check-ignore-rules` | gitignore 三态（台账入库 / 样本与产物不入库） | 全绿 |
| `fixtures` | 生成 `fixtures/out/` + `manifest.json` | 同 seed 逐字节一致 |
| `check-fixtures` | `fixture-gen --check` | 与入库 manifest 逐字节一致 |
| `smoke` | 构建 + 退出码 3 的两条冒烟 | 断言输出与退出码 |
| `cross` | 三平台交叉编译到 `dist/` | 全绿 |
| `all` | gates + verify-gates + check-ignore-rules + test + check-fixtures + smoke | 一键本地等价校验 |

实测（2026-10-27，本机）：`all` 全绿；`cross` 产出 linux/amd64、darwin/arm64、windows/amd64 三个产物；
`fixtures` 双跑 `diff -r` 为空，且与入库 manifest 逐字节一致。

### 2.4 CI 矩阵（`.github/workflows/ci.yml`）

| job | 内容 | 为什么单列 |
|---|---|---|

## 三、关键取舍（与 `plan/00` 决策 D1–D11 一致）

| 取舍 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 语言 | Go 单二进制 | Rust / Python | 交付物要求"单二进制、零运行时依赖"；Go 交叉编译最省事；Rust 也可但本机 cargo 生态未验证 |
| 生成器语言 | **Go**（同仓另一 main） | Python | 避免 Python 版本下限面（skill 实测：3.10+ 签名会在测试里复发）；生成器与 CLI 共用定点整数工具，但不共用解析器 |
| 解析器与生成器共享代码 | **不允许**（仅共享 `internal/policy` 常量） | 共享 IR | 生成侧写字节、生产侧读字节，方向相反；共享会让"真值 = 实现"变成自证 |
| JSON 库 | 标准库 `encoding/json` | 第三方 | 零依赖红线 |
| 报告排序 | 显式排序键 | map 遍历 | 确定性 |
| 错误处理 | `error` 返回 + 退出码 3；**不 panic** | panic/recover | 畸形输入不能让审计器崩 |
